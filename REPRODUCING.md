# Reproducing the figures and numerical evidence

Run the commands below from the repository root. Use a separate output directory so that the distributed data remain available for comparison.

```sh
python -m pip install -r requirements.txt
```

Python dependencies are listed in requirements.txt. Plotting uses LaTeX with Latin Modern. The full paired simulation uses a GNU/Linux C++17 compiler with OpenMP. Numerical outputs can depend on the compiler and mathematical library at the last floating-point digits.

## Rendering the supplied arrays

| Figure identifier | Available reproduction |
|---|---|
| `geometric_construction` | Vector PDF and construction coordinates are supplied. |
| `joint_window_phase_diagram` | Vector PDF represents the analytical regimes stated in the article. |
| `finite_horizon_phase_transitions` | `python code/finite_horizon_plot.py --output reproduced_figures` |
| `local_objective_geometry` | Included in the three-figure command below. |
| `measured_calibration_gains` | `python code/plot_calibration_gains.py --data data/measured_calibration_gains/expanded_calibration_results.csv --output reproduced_figures` |
| `stationary_calibration_comparison` | Uses the complete-objective data and refined sign-change brackets, with the dedicated command below. |

Render the finite-horizon phase, local-objective geometry and measured-gain figures together:

```sh
python code/render_figures.py --output reproduced_figures
```

This command reads the distributed arrays and produces those three PDFs. The original radial-Poisson solver used to generate the phase and local-objective arrays is available from the author on reasonable request. The arrays, discretization parameters and resolution comparisons are included for scientific inspection. Their renderers do not regenerate the underlying radial optimization.

Render the stationary-calibration comparison from its supplied tables:

```sh
python code/plot_stationary_calibration_comparison.py --data data/stationary_calibration_comparison/stationary_calibration_comparison.csv --brackets data/stationary_calibration_comparison/stationary_calibration_crossings.csv --output reproduced_figures
```

## Reconstructing the paired estimates

Recompute all 259 estimates, standard errors and pointwise confidence intervals from the 66,304 supplied block-moment rows:

```sh
python code/calibration_statistics.py --output reproduced_intervals.csv
```

The script pools within-block and between-block moments and compares the reconstruction with the published table. All scenarios within one horizon share input sequences. The seven horizon streams are independent. The intervals are pointwise and use the paired normal delta method.

## Regenerating paired trajectories

The following small run regenerates the first 128 trajectories at N=256:

```sh
python code/reproduce_expanded_calibration.py --output small_check --horizons 256 --trajectories 128 --threads 4
```

The complete expanded calculation is computationally intensive:

```sh
python code/reproduce_expanded_calibration.py --output reproduced_trajectories --threads 8
```

The random streams are specified by the supplied design and seed mapping; they do not depend on the number of threads or block boundaries. Existing blocks are reused after their parameters and checksums are verified. The published policy parameters are included. They can also be regenerated with:

```sh
python code/prepare_calibration_parameters.py --benchmarks code --root regenerated_parameters
```

## Exact and independent benchmarks

Regenerate the geometric constants, one-dimensional finite benchmark, scalar critical-window checks and symbolic identities:

```sh
python code/analytical_benchmarks.py
```

This program writes `check_results.json`, `dimension_constants.csv`, `exact_1d_finite.csv` and `critical_scalar_model.csv` in `code/`. The distributed reference outputs are in `data/analytical_benchmarks`. Dimension-dependent quadrature values for the constants table are in `data/dimension_constants`.

A separate three-case Monte Carlo cost check is available through `python code/finite_cost_monte_carlo.py`; it writes `finite_cost_monte_carlo.json` in `code/`. The twelve-scenario comparison with a numerical finite-horizon reference is regenerated by:

```sh
python code/calibration_experiment.py --output reproduced_reference_comparison
```

Its complete stored trajectory arrays are supplied in `SupplementaryMaterial3.zip`. Extract that archive into the same directory as `SupplementaryMaterial2.zip`; it installs `data/calibration_experiment/calibration_trajectory_costs.npz` alongside the supplied tables. The regeneration command produces new arrays without requiring that download. The numerical reference parameters are fixed inputs in `code/calibration_reference_parameters.csv`; regenerating the trajectories uses those supplied parameters.

## Stationary-objective comparisons

The moment method uses radial recurrences, a potential series and binary summation of the finite horizon. The mathematical derivation and numerical qualifications appear in [Supplementary Material 1](SupplementaryMaterial1.pdf). The complete comparison data are in `data/stationary_calibration_comparison`. The method distinguishes analytical series truncation, floating-point arithmetic and numerical minimization over a continuous parameter interval. It does not supply a certificate of global continuous minimization.

Regenerate the full comparison and then refine its observed sign-change brackets:

```sh
python code/stationary_calibration_comparison.py --output reproduced_stationary --orders 40 64 96
python code/stationary_calibration_crossings.py --data reproduced_stationary/stationary_calibration_comparison.csv --output reproduced_stationary --width 0.0001
```

The first command writes the complete comparison and its design JSON. Adding `--pilot` selects a smaller check of the method. The second command writes bracket endpoints and every additional evaluation used in the refinement. The brackets depend on the numerical sign checks described in the supplement and are not continuous-domain certificates.

## Exact and high-precision validation of the moment method

The comparison can be checked against formulas for the first radial moment and quadratic costs, exact disk potentials, and independent high-precision moment calculations. This separates tests of the implementation from changes between series orders, which measure only part of the numerical error. Reproduce the 78 recorded checks with the supplied twelve-case design:

```sh
python code/validate_stationary_calibration.py --solver code/stationary_calibration_comparison.py --cases data/stationary_calibration_comparison/numerical_validation_cases.csv --output reproduced_validation
```

The program uses 100 decimal digits by default and writes `numerical_validation.csv`, `high_precision_reference_cases.csv` and `numerical_validation.json` in the selected output directory. The CSV records each compared quantity, reference method, absolute difference and tolerance; the JSON records the solver checksum, arithmetic precision, check count and whether every comparison satisfied its tolerance. The supplied reference outputs are in `data/stationary_calibration_comparison`.

These checks cover the listed numerical cases, including selected sign-change endpoints. They do not provide interval bounds for every floating-point calculation or certify global minimization over the continuous parameter interval. The reported NumPy extended-precision type can vary across platforms, so retain the generated precision metadata when comparing results.
